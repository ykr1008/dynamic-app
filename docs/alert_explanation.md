The vulnerability occurred because `innerHTML` interpreted the user-supplied task title as HTML instead of treating it as plain text. An attacker could inject malicious HTML containing JavaScript event handlers, such as an image with an `onerror` attribute. When the browser processed the injected element, the JavaScript executed, demonstrating a Cross-Site Scripting (XSS) vulnerability. I fixed this by replacing `innerHTML` with `textContent`. The `textContent` property displays the supplied value as text and does not parse it as HTML, so the injected markup cannot create executable elements. This reduces the risk of script injection through task titles.
